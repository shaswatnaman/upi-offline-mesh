📡 MeshPay — UPI Offline Mesh

Send money with zero internet. Payment packets are encrypted on the sender's phone and gossip from device to device over Bluetooth/WiFi-Direct until a bridge node with 4G reaches the backend and settles the transaction.

Hybrid Encryption — Server RSA public key encrypts a random AES session key. Only the server private key can decrypt the payment.
Gossip Protocol — Each phone forwards packets to neighbours until TTL reaches 0 or a bridge delivers it.
Idempotency — Multiple bridge nodes may upload the same packet. The backend deduplicates using a packet hash.
Plain JDBC DAO — LedgerJdbcDao uses raw PreparedStatements (not JPA) for audit queries.
1 Compose Payment

Simulates the sender's phone. Fetches the server's RSA public key, generates a random AES-256 session key, encrypts the payment, and packs it into a MeshPacket.

→
₹ PIN
What happened: A random AES-256-GCM key was generated in-memory. The payment data was encrypted with it. The AES key itself was then wrapped with the server's RSA-2048 OAEP public key. Only the server can unwrap the AES key to read the payment. The packet was placed on phone-alice in the mesh.
2 Run Gossip Round

Each offline phone forwards packets to its neighbours (random selection). TTL decrements each hop. Run multiple rounds to spread packets across the mesh — like epidemic broadcast.

What happened: The simulator picked a random neighbour for each device and transferred packets that the neighbour didn't already hold. TTL decremented. When TTL hits 0, the packet can't hop further — it must be uploaded by whichever device holds it.
3 Bridge Uploads to Backend

The bridge node(s) get 4G and simultaneously POST all held packets to /api/bridge/ingest. Parallel uploads test idempotency — duplicates are detected by packet hash and dropped.

What happened: Bridge nodes uploaded packets in parallel (using Java's parallelStream). The backend checked each packet hash in the idempotency cache. First arrival → decrypted, verified, balances updated, written to DB via JPA + JDBC. Subsequent arrivals of the same hash → DUPLICATE_DROPPED.
